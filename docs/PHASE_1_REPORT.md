## 5. How the frontend connects (the thin adapter)

```
Frontend/main.py (UNCHANGED)
   └── Backend/bridge.py::AssistantBridge
         ├── (existing) VoiceListener → BrainWorker → AssistantBrain → SpeechPlayer
         └── (NEW, opt-in) self.gateway = attach_gateway_mirror(self, os.getenv("STAR_GATEWAY_URL"))
                ├── mirror_query(text)      → POST /api/v1/ui   {type: ui.state, state: think}
                ├── mirror_response(text)   → POST /api/v1/ui   {type: ui.state, state: speak}
                ├── mirror_state(state)     → POST /api/v1/ui
                ├── send_text(text)         → POST /api/v1/chat (STAR 2.0 brain, from Phase 3)
                ├── resolve(id, approve)    → POST /api/v1/confirmations
                ├── stop_all()              → POST /api/v1/stop
                └── StarGatewayStream       → WS /ws (falls back to GET /api/v1/events?since=)
```

Properties that matter:
* **`STAR_GATEWAY_URL` unset ⇒ literally nothing changes.** `attach_gateway_mirror` returns `None`,
  `_gw()` is a no-op, no thread is started, no import of `Backend.star` happens.
* All mirror calls are fire-and-forget on one bounded worker thread — the Qt UI thread never blocks.
* After `max_failures` (6) unreachable calls the mirror **disables itself** and logs once.
* `Backend/star/gateway/frontend_adapter.py` is Qt-free, so it is unit-tested headless.
* Agent internals never reach the frontend: the adapter only sees `StarEvent` JSON.

## 7. Risks

1. **Hand-rolled transport.** No framework means no framework's security patches. Mitigations:
   strict request-head limits, `max_body_bytes`, 8 MiB WS frame cap, 413 on overflow, idle ping +
   drop, `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`, CORS only for configured
   origins. Bind to `127.0.0.1` in production (`STAR_GATEWAY_HOST`), `0.0.0.0` only for dev/preview.
2. **Python 3.12+ shutdown semantics.** `Server.wait_closed()` now waits for live connections;
   the first implementation deadlocked when a client vanished mid-session. Fixed by cancelling
   connection tasks first and time-boxing both awaits (`shutdown_timeout=5s`) + WS idle timeout.
   Regression-covered by the WS tests' `finally: writer.close()`.
3. **Phase 1 chat = legacy router.** Real tools are executed (e.g. `set_volume`) — safe here because
   motor actions go through `agent`'s governor and `STAR_DRY_RUN=true` is the default, but the
   router's own tool calls are **not** yet policy-classified. That is exactly what Phase 4 + 11 add;
   until then the gateway must stay in dry-run.
4. **Placeholder endpoints.** `/api/v1/tools|agents|memory|audit|workspaces|confirmations` return
   valid-but-empty payloads (or `{"pending": true, "phase": N}`). The console labels them; no caller
   should infer capability from a 200 alone.
5. **Ops console ≠ product UI.** It is a diagnostics bench. The Star HUD remains the visible Star.
